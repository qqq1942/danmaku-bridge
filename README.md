# B站弹幕 → 泰拉瑞亚服务器

两条通路：

```
B站弹幕 WebSocket
      ├─ 普通弹幕 ─────────────→ TShock REST /v2/server/broadcast ──→ 游戏聊天栏
      │
      └─ 刷怪指令 "/刷怪"（也可以 /刷怪 僵尸 3 饺子喵喵）
                │  解析 / 鉴权 / 限速
                └─→ TShock REST /v3/server/rawcmd  →  /dspawn @观众
                                                      ↓
                                             服务端插件 DanmakuSpawn
                                  随机一只安全怪 → NPC.NewNPC → 随机在线玩家身边
```

**玩家不需要装任何模组**，原版客户端就有效果——全部在服务端完成。

## 依赖

| 通路 | 依赖 |
|---|---|
| 弹幕 → 聊天栏 | 只需要 TShock REST |
| 弹幕 → 刷怪 | 额外需要服务端插件 `DanmakuSpawn`（`~/terraria/danmaku-spawn/`，装法见那里的 README）|

插件没装也能跑：桥接启动时会用 `/dspawn status` 探测插件，**没装就静默跳过指令**（不会往游戏里刷
"Invalid command entered" 这种失败提示），普通弹幕照常转发。装好插件、重启服务器之后，
桥接会在 45 秒内自动探测到并接管，不用改配置。

## 快速开始

```bash
cd ~/terraria/danmaku-bridge

# 基本用法（forward 弹幕 + 开指令）
ROOM_ID=23343237 node danmaku-bridge.js

# 后台常驻
setsid nohup env ROOM_ID=23343237 node danmaku-bridge.js > /dev/null 2>&1 &

# 停止
pkill -f danmaku-bridge.js
```

## 自检（不连直播间也能验证链路）

```bash
# 假装观众"白嫖怪"发了一条指令，跑通 桥接 → REST → 插件 整条链路
ROOM_ID=selftest SELFTEST_CMD='!刷怪 僵尸 2 @spawn' SELFTEST_USER='白嫖怪' node danmaku-bridge.js
```

输出里出现 `指令受理: [刷怪] 已排队：2 只「Zombie」→ 世界出生点` 就说明整条链路通了。
`@spawn` 表示刷在世界出生点（没有玩家在线时也能验证）。

## 弹幕指令

### 最常用：只发 `/刷怪`

```
/刷怪
```

→ 服务端随机挑**一只安全怪**（不会拆方块、不是 BOSS/分段怪），刷到**随机一个在线玩家**身边。
观众不用记怪物名，最省事。

### 想指定怪物 / 数量 / 玩家（可选）

```
/刷怪 <怪物> [数量] [玩家]
```

| 弹幕 | 效果 |
|---|---|
| `/刷怪` `!刷怪` `#spawn` | 随机怪 + 随机玩家（主用法）|
| `/刷怪 僵尸` | 1 只僵尸，刷在随机在线玩家附近 |
| `/刷怪 僵尸 3` | 3 只 |
| `/刷怪 僵尸 3 饺子喵喵` | 3 只，刷在「饺子喵喵」附近 |
| `/刷怪 史莱姆 5 饺子喵喵` | 中文别名由插件解析（见 `/dspawn list`）|
| `/刷怪 Blue Slime 2` | 英文名也行，指令词 `spawn` 和 `刷怪` 等价 |
| `/召唤 猪鲨` | `召唤` / `出怪` 也是等价指令词 |
| `！刷怪` | 全角感叹号也认 |

前缀支持 `!` `/` `#` `！`；指令被受理后，游戏内会看到：

```
【弹幕】白嫖怪 召唤了 1 只 Mummy 在 饺子喵喵 附近！
```

失败原因也会播报到游戏聊天栏（例如"「Moon Lord」在黑名单里"）。

**哪些怪会被随机到**：插件配置 `RandomMobs` 里那 60 多种常见敌对怪（史莱姆/僵尸/骷髅/黄蜂/
地牢怪/困难模式怪……），BOSS、分段怪、城镇 NPC、会扔炸弹拆方块的小丑一律不在池子里。
服务器上 `/dspawn pool` 可以看到完整随机池，`/dspawn pool 2` 翻页。

## 可配置项

### 普通弹幕转发

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `ROOM_ID` | **必填** | B站直播间号（短号/长号都行）|
| `REST_TOKEN` | 读 `../.rest_token` | TShock REST token |
| `MAX_PER_MIN` | `12` | 每分钟最多转发条数（防刷屏）|
| `PREFIX` | `[弹幕]` | 游戏内显示的前缀 |
| `MIN_LEN` | `1` | 最短转发长度 |
| `MAX_LEN` | `50` | 最长转发长度（超出截断）|
| `BLOCK_WORDS` | 空 | 屏蔽词，逗号分隔 |
| `SESSDATA` | 空 | **可选**，B站登录 cookie，一般不需要（见 FAQ）|

### 刷怪指令

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `CMD_ENABLE` | `1` | 是否开启指令（`0` 关）|
| `CMD_PREFIX` | `!` | 指令前缀（`/` `#` `！` 也认）|
| `CMD_WORDS` | `刷怪,spawn,召唤,出怪` | 指令词，逗号分隔 |
| `CMD_MAX_AMOUNT` | `5` | 单条指令最多几只（插件侧还有一层 `MaxAmount`）|
| `CMD_DEFAULT_AMOUNT` | `1` | 不写数量时刷几只 |
| `CMD_MAX_PER_MIN` | `6` | 全服每分钟最多几条指令 |
| `CMD_USER_COOLDOWN` | `30` | 同一观众冷却秒数 |
| `CMD_MIN_GUARD` | `0` | 最低舰长等级：`0` 不限，`3` 舰长，`2` 提督，`1` 总督 |
| `CMD_MIN_MEDAL` | `0` | 最低粉丝牌等级（0=不限，可设 5 只给牌子党玩）|
| `CMD_ALLOW` | 空 | 白名单观众（逗号分隔，填了就只有这些人能用）|
| `CMD_BLOCK` | 空 | 黑名单观众（逗号分隔）|
| `CMD_DEFAULT_PLAYER` | 空 | 没指定玩家时固定刷谁附近（留空=插件自己随机）|

示例（只给舰长用、每人 1 分钟一次、最多 3 只）：

```bash
ROOM_ID=23343237 CMD_MIN_GUARD=3 CMD_USER_COOLDOWN=60 CMD_MAX_AMOUNT=3 \
  CMD_MAX_PER_MIN=10 node danmaku-bridge.js
```

> 随机模式下 `CMD_MAX_AMOUNT` 不影响数量——数量由插件配置里的 `RandomAmount` 决定（默认 1 只）。

## 已实现的健壮性

| 特性 | 说明 |
|---|---|
| **WBI 签名** | B站新版接口做了风控（`-352`），脚本自动处理签名 |
| **节点轮换** | 部分弹幕节点对某些房间不推数据，60 秒无数据自动换下一个节点 |
| **自动重连** | 断线指数退避重连（3s → 60s 封顶）|
| **限速（转发）** | 每 5 秒最多发 1 条，且每分钟不超过 `MAX_PER_MIN` 条 |
| **限速（指令）** | 全服 `CMD_MAX_PER_MIN`/分 + 单观众 `CMD_USER_COOLDOWN` 秒冷却 |
| **鉴权** | 舰长等级、粉丝牌等级、白/黑名单 |
| **参数清洗** | 滤掉 `/ \ ; & = ? # 引号 换行` 等能掺进命令行的字符，单词最长 20 字，最多 4 个词 |
| **不刷屏** | 指令被吃掉，不会再当普通弹幕转发一遍 |
| **防积压** | 转发队列超 50 条直接丢弃 |

## 常见问题

**Q: 连上了但一直没有弹幕？**

A: 检查房间是否真的在直播且有聊天。实测：
- 热门直播间弹幕源源不断
- 部分房间（尤其**轮播/回放**）`live_status=1` 但**没有任何弹幕**，只收到"观众进入"事件

**Q: 弹幕太多刷屏？**

A: 调小 `MAX_PER_MIN`，或用 `BLOCK_WORDS` 过滤。

**Q: 指令发了没反应？**

A:
1. 看 `bridge.log` 有没有"指令:"这行——没有说明前缀/指令词没匹配上
2. 有"指令被拒"就按提示改（冷却、限速、舰长门槛）
3. 插件没装的话 REST 会回 `Invalid command entered`
4. `/dspawn status` 看队列是否在动（`tick=0` 空服时靠兜底线程，见插件 README）

**Q: 观众名字带空格或奇怪符号？**

A: 会被清洗（去掉 `/\;&=?#` 等），作为 `@观众名` 只用于播报，不影响刷怪本身。

## 需要登录 B站账号吗？

**不需要。匿名就能收弹幕。**

实测（2026-10-24，房间 23343237）匿名连接完全正常，弹幕可以收到并转发进游戏。

登录（`SESSDATA`）能带来的差异：

| 场景 | 匿名 | 登录 |
|---|---|---|
| 收弹幕 | ✅ | ✅ |
| `getDanmuInfo` 风控（-352）| ✅ 已用 WBI 签名解决 | ✅ |
| 付费/粉丝限定房间 | ⚠️ 可能受限 | ✅ |
| API 频率限制 | 较严 | 较宽松 |

**但登录也有代价**：`SESSDATA` 几周到几个月就过期，过期后脚本会静默失败；用个人账号跑自动化有被风控的风险；账号 cookie 要存放在服务器上。

**建议：先别登录。** 只有遇到"某个房间匿名收不到弹幕"时再用：

```bash
SESSDATA='你的SESSDATA' ROOM_ID=12345 node danmaku-bridge.js
```

获取方法：浏览器登录 B站 → F12 → Application → Cookies → 复制 `SESSDATA` 的值。

## 技术细节

- 纯 Node.js 实现，**零 npm 依赖**（内置 `fetch` / `WebSocket` / `zlib.brotliDecompressSync`）
- B站弹幕协议：WebSocket + 二进制包（4 字节总长 / 2 字节头长 / 2 字节版本 / 4 字节操作码 / 4 字节序号）
- `protover: 3` 表示正文用 brotli 压缩
- `DANMU_MSG` 的 `info[1]` 是弹幕文本，`info[2][1]` 是用户名，`info[3][0]` 是粉丝牌等级，`info[7]` 是舰长等级
- 刷怪走 `/v3/server/rawcmd`（TShock 6 才有这个端点；`/v2/server/rawcmd` 返回 404）
